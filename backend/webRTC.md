Works on UDP protocol

NAT -> Network Address Translation
NAT Translation methods
    - One to One (Full Cone nat) -> Packets to External IP:Port on the router always maps to internal IP:Port without exceptions
    - Address restricted NAT -> only address is restricted 
    - Port restricted NAT -> port and address both are restricted
    - Symmetric NAT -> only allow if the full pair of external and internal ip and port matches

STUN -> Session Traversal utilities for NAT
    - Does not work for Symetric NAT
    - What is the work of this STUN
    - Cheap to maintain and run

TURN -> Traversal Using Relays around NAT
    - In case of symetric NAT, we use TURN
    - It's just a server that relays packets
    - Expensive to maintain and RUN

ICE -> Interactive Connection Established
SDP -> Session Description Protocol
    - A format that describes ice candidates, networking options, media options, security options and other stuff
    - The goal is to take the SDP generated by a user and send it somehow to the other party

Signaling 
    - Send the SDP that we generated somehow to the other party we wish to communicate
    - Signalling can be done via a tweet, QR Code, What'sApp or http req
    - And to simplify this, we create a socket server to help exchange those SDPs  

DrawBack -> p2p connection
    - only 2 people can connect
    - a work around is a mesh, ie every client is connected to everyone else in the netwoork. but scalability is the issue and is not recommended
    - So SFU(Selective Forwarding Unit) is preferred if we want multiple connections
